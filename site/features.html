The router does the work

Picking, failing over, hiding keys and counting tokens.

Picks the best model

Every request is routed to the fastest model that can serve it, chosen from your ordered fallback chain. In a typical week 62% of requests land on the first choice, 31% on the second and 7% on a fallback.

Falls over on rate limits

When a provider throttles or hits its cap, the next provider takes the request before your caller sees it. Order is yours: for example OpenAI, then Anthropic, then Google.

Keeps keys encrypted

Provider keys are encrypted at rest. Clients only ever see one unified key, minted in the dashboard.

Counts tokens per key

Usage is tracked per key against every provider's free-tier cap, so you never quietly pass a limit.
